# Formatta (DocGen)

Веб-инструмент для сборки и проверки документов по смысловым шаблонам: FAQ, Use Case, техническое задание, Release Notes, API-документация и пр.

Formatta берет исходные материалы пользователя (DOCX, PDF, TXT, Markdown, изображения, страницы Confluence), собирает из них рабочий документ по выбранному шаблону, дает править его вручную или через чат, проверяет на соответствие шаблону и выгружает в нужном формате с корпоративным оформлением. Обработка идет локальными моделями внутри корпоративного контура; документ не дополняется общими знаниями модели — только сведениями из добавленных пользователем источников.

## Зачем

- сократить ручную работу при подготовке типовых документов;
- обеспечить проверку по структуре, полноте, терминологии, непротиворечивости и стилю — с указанием, на основании какой цитаты источника принято каждое решение;
- держать единый корпоративный вид документа независимо от того, кто и как его собирал.

Подробное описание сценариев, целевых метрик и понятий — в [`PRD.md`](PRD.md).

## Как это устроено

- **Смысловой шаблон** — что должно быть в документе: разделы, обязательные таблицы и поля, правила проверки (структура/полнота/терминология/непротиворечивость/стиль). Хранится в YAML, редактируется администратором, не пользователем. 
- **Шаблон оформления** — как это выглядит в конкретном выходном формате (DOCX/HTML/PDF/Markdown): стили, поля, колонтитулы, брендирование. Не связан со смысловым составом.
- **Рабочий документ** — внутреннее, независимое от формата представление: разделы, абзацы, списки, таблицы, изображения, отметки о пробелах. Редактор и чат правят именно его; финальный файл собирается из него при экспорте.
- **Проверка по шаблону** — отдельный проход модели по четким правилам шаблона, результат — список подтвержденных находок (с цитатой-обоснованием и, где возможно, готовым исправлением), а не открытый диалог.

Веб-процесс (FastAPI) кладет длительные операции — сборку, проверку, экспорт — в очередь SQLite; отдельный worker забирает их и выполняет. Интерфейс — Jinja2 + HTMX, без сборки фронтенда и внешних CDN.

## Быстрый старт

```bash
python -m venv app/.venv
app/.venv/bin/python -m pip install -e 'app[dev]'

# в одном терминале
app/.venv/bin/uvicorn docgen.main:app --app-dir app/src --port 8000

# в другом терминале
DOCGEN_WORKER_ID=formatta-local-1 app/.venv/bin/python -m docgen.jobs.worker
```

Интерфейс — `http://127.0.0.1:8000/projects`. Либо одной командой через Docker:

```bash
docker compose up --build
```

Полная инструкция — установка на Windows, конфигурация переменных окружения, лимиты, тесты, деплой в Dokploy, ручная приемка сценария — в [`app/README.md`](app/README.md).

## Тесты

```bash
cd app
.venv/bin/python -m pytest -v
.venv/bin/python -m ruff check .
```

Тесты используют только синтетические данные и локальные fake-модели — сети, реальных моделей и корпоративного Confluence не касаются.
