# Formatta

Formatta — локальное веб-приложение для работы с источниками, сборки документов по смысловым шаблонам и проверки загруженных или собранных документов. Веб-процесс ставит длительные операции в SQLite-очередь, а отдельный worker выполняет их и сохраняет документ и отчёт.

## Установка

Команды POSIX (из корня репозитория DocGen):

```bash
python -m venv app/.venv
app/.venv/bin/python -m pip install -e 'app[dev]'
```

Команды Windows PowerShell (из корня репозитория):

```powershell
cd app
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

## Запуск web и worker

Web и worker должны работать одновременно в двух терминалах. Если OpenAI-совместимый endpoint локальной text-модели не запущен как сервис, ему нужен ещё один терминал. Все команды ниже выполняются из корня репозитория DocGen.

POSIX, терминал web:

```bash
app/.venv/bin/uvicorn docgen.main:app --app-dir app/src --port 8000
```

POSIX, терминал worker:

```bash
DOCGEN_WORKER_ID=formatta-local-1 app/.venv/bin/python -m docgen.jobs.worker
```

`DOCGEN_WORKER_ID` задаётся именно в окружении worker-процесса. Его значение должно быть стабильным и уникальным для каждого одновременно запущенного worker.

Windows PowerShell, терминал web:

```powershell
cd app
.\.venv\Scripts\python.exe -m uvicorn docgen.main:app --port 8000
```

Windows PowerShell, терминал worker:

```powershell
cd app
.\.venv\Scripts\python.exe -m docgen.jobs.worker
```

Интерфейс доступен по `http://127.0.0.1:8000/projects`.

## Запуск через Docker

Из корня репозитория можно запустить web и worker одной командой:

```bash
docker compose up --build
```

Compose собирает один локальный образ `docgen:local` и запускает два сервиса:

- `web` — FastAPI/uvicorn, порт `8000`;
- `worker` — обработчик очереди `python -m docgen.jobs.worker`.

Интерфейс будет доступен по `http://127.0.0.1:8000/projects`.

Runtime-данные SQLite и загруженные файлы хранятся в volume `docgen-var`.
Файл `.env` не копируется в Docker-образ и исключён из build context через `.dockerignore`;
compose подключает его только во время запуска через `env_file`.

Минимальная конфигурация для text-only сборки:

```env
DOCGEN_LOCAL_TEXT_BASE_URL=https://example.local
DOCGEN_LOCAL_TEXT_MODEL=model-name
DOCGEN_LOCAL_TEXT_API_KEY=replace-with-local-secret
DOCGEN_TRUSTED_INTEGRATION_HOSTS=["localhost","127.0.0.1","::1","example.local"]
```

Для внешней Confluence и vision-модели используются те же переменные `DOCGEN_*`,
которые перечислены ниже в разделе конфигурации.

## Конфигурация

При запуске из исходного репозитория `Settings` автоматически загружает `.env` из корня репозитория; переменные окружения процесса имеют приоритет. У установленного wheel `.env` ищется в текущей рабочей директории. Вручную выполнять `. ./.env` для полей `Settings` не требуется. `DOCGEN_WORKER_ID` читается worker напрямую из окружения процесса и не является полем `Settings`.

Поддерживаются все следующие имена:

- `DOCGEN_DATABASE_URL` — URL базы SQLAlchemy;
- `DOCGEN_DATA_DIR` — каталог загруженных файлов;
- `DOCGEN_CONFLUENCE_HOSTS` — JSON-массив разрешённых имён хостов Confluence;
- `DOCGEN_TRUSTED_INTEGRATION_HOSTS` — JSON-массив доверенных хостов исходящих AI/API-запросов; по умолчанию только `localhost`, `127.0.0.1` и `::1`;
- `DOCGEN_CONFLUENCE_API_BASE` — базовый URL Confluence REST API;
- `DOCGEN_CONFLUENCE_TOKEN` — токен Confluence;
- `DOCGEN_LOCAL_TEXT_BASE_URL` — базовый URL OpenAI-совместимой текстовой модели;
- `DOCGEN_LOCAL_TEXT_MODEL` — имя текстовой модели;
- `DOCGEN_LOCAL_VISION_BASE_URL` — базовый URL OpenAI-совместимой мультимодальной модели;
- `DOCGEN_LOCAL_VISION_MODEL` — имя мультимодальной модели;
- `DOCGEN_WORKER_ID` — стабильный уникальный идентификатор worker-слота;
- `DOCGEN_WORKER_LEASE_SECONDS` — срок аренды задания worker-процессом, по умолчанию `30` секунд;
- `DOCGEN_MAX_UPLOAD_BYTES` — предел одного загружаемого файла, по умолчанию `52428800` (50 МиБ);
- `DOCGEN_MAX_PROJECT_STORAGE_BYTES` — предел суммарных файлов проекта, по умолчанию `524288000` (500 МиБ);
- `DOCGEN_MAX_IMAGE_PIXELS` — предел числа пикселей изображения, по умолчанию `40000000`;
- `DOCGEN_MAX_ARCHIVE_ENTRIES` — предел записей DOCX-архива, по умолчанию `10000`;
- `DOCGEN_MAX_ARCHIVE_UNCOMPRESSED_BYTES` — предел распакованного DOCX, по умолчанию `209715200` (200 МиБ);
- `DOCGEN_MAX_MODEL_REQUEST_BYTES` — предел сериализованного запроса к модели, по умолчанию `20971520` (20 МиБ);
- `DOCGEN_MAX_JOB_SECONDS` — предел задания на кооперативных контрольных точках, по умолчанию `300` секунд.
- `DOCGEN_TEMPLATE_DIR` — относительный от корня репозитория или абсолютный путь к каталогу YAML-смысловых шаблонов администратора.

Секреты хранятся только в корневом `.env`. Не печатайте его содержимое, не копируйте значения в команды, код, конфигурацию или заметки и не добавляйте `.env` в Git.

Web запускается без настроенных моделей и Confluence. Worker также может собрать зависимости без этих необязательных интеграций, но не запускается без `DOCGEN_WORKER_ID`. Запуск сборки или проверки возвращает `503`, пока не настроена текстовая модель. Vision-модель нужна только для источников с изображениями: если она не настроена, text-only задания работают, а задание с изображением завершается с понятной ошибкой. Для документа с источником Confluence операция дополнительно возвращает `503`, пока не настроены API и токен Confluence.

Пять встроенных YAML — стартовые смысловые шаблоны. Чтобы подключить корпоративный шаблон, создай YAML-файл в отдельном каталоге и укажи его в `.env`, например `DOCGEN_TEMPLATE_DIR=config/semantic-templates`. Новый `id` добавляет шаблон в список; файл с тем же `id`, например `faq`, заменяет встроенный вариант. После изменения шаблонов перезапусти web и worker.

Адреса моделей и `DOCGEN_CONFLUENCE_API_BASE` должны использовать HTTP(S), не содержать логин, пароль или фрагмент и иметь хост из `DOCGEN_TRUSTED_INTEGRATION_HOSTS`. Хост пользовательской страницы Confluence независимо проверяется по `DOCGEN_CONFLUENCE_HOSTS`. Интерфейс использует только локальные упакованные HTMX/CSS-ресурсы и не требует CDN.

## Текущие ограничения

- Поддерживаются `.docx`, `.pdf`, `.txt`, `.md`, `.png`, `.jpg`, `.jpeg` и `.webp`. Для автономной проверки целевым документом могут быть только DOCX, PDF, TXT или Markdown.
- Общий объём проекта ограничен 150 расчётными страницами. Начиная со 101 страницы показывается предупреждение о возможной обработке дольше пяти минут.
- Один файл ограничен 50 МиБ, файлы проекта — 500 МиБ; значения настраиваются переменными выше. Лимиты проверяются до полного чтения/декодирования, а незавершённые загрузки удаляются.
- Ответ локальной модели ограничен 10 МБ, сериализованный запрос — 20 МиБ, тайм-аут запроса — 120 секунд.
- Ответ Confluence ограничен 5 МБ, суммарный объём его загруженных вложений-изображений — 5 МБ, тайм-аут каждого запроса — 30 секунд.
- Для одного проекта одновременно допускается только одно задание в очереди или в работе. Worker поддерживает аренду с фоновым heartbeat; отмена и предел времени задания проверяются кооперативно между внешними этапами. После ошибки или отмены интерфейс предлагает повторный запуск.

## Тесты качества и приёмка Stage 2

Тесты используют только синтетические данные, локальные детерминированные fake-модели и `MockTransport`; они не обращаются к сети, реальным моделям или корпоративному Confluence. Замороженный банковский пример вымышлен и не содержит реальных корпоративных данных.

POSIX:

```bash
cd app
.venv/bin/python -m pytest tests/quality tests/test_stage2_journey.py -v
.venv/bin/python -m pytest -v
.venv/bin/python -m ruff check .
```

Windows PowerShell:

```powershell
cd app
.\.venv\Scripts\python.exe -m pytest tests\quality tests\test_stage2_journey.py -v
.\.venv\Scripts\python.exe -m pytest -v
.\.venv\Scripts\python.exe -m ruff check .
```

На Windows без права создания символических ссылок два теста безопасности хранилища могут завершиться до выполнения кода приложения с `WinError 1314`. Для такой среды разрешённый полный прогон исключает только:

- `tests/sources/test_storage.py::test_save_rejects_projects_directory_symlinked_outside_data_dir`;
- `tests/sources/test_storage.py::test_delete_project_rejects_symlink_to_another_project`.

## Сброс локальных данных

Остановите web и worker. Затем удалите только фактические пути базы и данных, заданные `DOCGEN_DATABASE_URL` и `DOCGEN_DATA_DIR`. Сначала разрешите и проверьте точные абсолютные пути; не используйте широкий рекурсивный путь, glob или корень workspace.

## Восстановление после ошибки очистки файлов

Удаление проекта или источника фиксирует транзакцию базы до удаления локальных файлов. Если последний шаг не удался, Formatta пишет `project_cleanup_failed` или `source_cleanup_failed` с идентификаторами и относительным путём.

После исправления доступа остановите процессы и удалите только записанный путь внутри `DOCGEN_DATA_DIR`. Для источника это точный относительный путь из журнала; для проекта — каталог `projects/<project-id>`. Убедитесь, что разрешённый путь остаётся внутри `DOCGEN_DATA_DIR`, затем перезапустите Formatta.

## Ручная приёмка рабочего сценария

Для прогона нужна настроенная локальная text-модель и одновременно запущенные web и worker. Vision-модель для Markdown без изображений не нужна.

1. Создай документ и загрузи в него Markdown-источник.
2. Выбери смысловой шаблон FAQ.
3. Нажми «Собрать» и дождись завершения задания.
4. Измени текст в визуальном редакторе и нажми «Сохранить».
5. Задай в чате правку, которая подтверждается исходником.
6. Запусти «Проверить по шаблону» для текущего документа.
7. Выбери загруженный Markdown в поле «Документ для проверки» и повтори проверку.

## Редактор и чат

Редактор доступен по `/projects/{project_id}/editor` для текущего сохранённого `WorkingDocument`. Поддерживаются блоки `heading`, `paragraph`, `list`, `table`, `image` и `gap`; вставка из UI открыта для разделов, абзацев, списков и таблиц. Изображения редактируются как метаданные: выравнивание, ширина и alt-текст.

Каждая ручная правка применяет ожидаемый `revision`. При успехе документ автоматически сохраняется, ревизия увеличивается, а старый отчёт проверки инвалидируется. Если клиент отправляет устаревшую ревизию, сервер возвращает `409` и просит обновить рабочую область; тихая перезапись не выполняется.

Чат принимает одно сообщение и возвращает видимую сводку ответа. История чата не хранится. План правок должен ссылаться на известные evidence block IDs; если для фактической правки нет подтверждения в источниках, документ не меняется и интерфейс получает `422`.

Повторная проверка через `/projects/{project_id}/jobs/check` использует текущий сохранённый `WorkingDocument`, если пользователь не выбрал отдельный target source. Новый отчёт привязывается к ревизии документа, которую он проверил.
