# DocGen Stage 3.1: готовность MVP

## Цель

Довести уже реализованные этапы 2–3 до работающего пользовательского сценария: пользователь загружает источник, запускает сборку или проверку, получает понятный результат или конкретную безопасную причину ошибки.

## Граница работ

- Внешне `Project` называется «Документом»; внутренняя модель и таблицы не переименовываются.
- Корневой `.env` загружается при запуске и web, и worker из любой рабочей директории.
- Текстовая модель обязательна для AI-операций. Vision-модель запрашивается worker только при фактической обработке изображения.
- Ошибка задания показывается пользователю безопасно и конкретно.
- Чат получает evidence из нормализованных исходников, а не из редактируемого документа.
- Проверка стартует от выбранного исходника; название нового документа предлагается из имени первого источника и остаётся редактируемым.
- Семантические YAML-шаблоны администратора загружаются из внешнего каталога, заданного настройкой. Пять встроенных шаблонов — только стартовый набор: внешний файл с тем же `id` заменяет встроенный, файл с новым `id` добавляет новый шаблон. Число и набор ID не фиксируются.

## Исключения

Экспорт, шаблоны оформления, пользовательский конструктор шаблонов, роли и миграция внутренней сущности `Project` не входят в этап 3.1.

## Проверка

Для каждого изменения добавляется регрессионный тест. Завершение подтверждается полным `pytest` и `ruff check .`; реальный OpenAI-compatible endpoint проверяется отдельно после предоставления его конфигурации.
