# Formatta 3.1.1: стабилизация рабочего экрана

## Цель

Довести новый рабочий экран Formatta до сценария MVP: пользователь загружает источник, собирает или проверяет документ с выбранным смысловым шаблоном, редактирует результат и повторно проверяет его без потери структуры и подтверждённых фактов.

Этап 4 (экспорт и шаблоны оформления) не входит в работу.

## Границы

- Не добавлять авторизацию, экран входа, иллюстрации или новый брендовый контент.
- Пользовательский бренд и название продукта — только `Formatta`; `DocGen` остаётся допустимым лишь во внутренних именах Python-модулей и переменных окружения для обратной совместимости.
- Использовать спокойную цветовую логику корпоративных интерфейсов SOVA и TrackStudio.
- Не менять модель данных проектов, источников, заданий и смысловых YAML-шаблонов.

## Проверка по шаблону

Верхний селектор шаблона является единым источником выбранного `template_id` и для сборки, и для проверки.

Кнопка «Проверить по шаблону» доступна, когда есть текущий собранный документ либо хотя бы один загруженный поддерживаемый файл. При одном подходящем файле он отправляется для проверки автоматически. При нескольких файлах пользователю доступен выбор файла. Проверка текущего собранного документа сохраняет существующее правило совместимости его `template_id` с выбранным шаблоном.

## Редактор, структура и grounding

Визуальный HTML редактора является представлением смыслового рабочего документа. Каждый редактируемый верхнеуровневый элемент связан с узлом через `data-node-id`. При сохранении сервер разбирает разрешённый HTML и обновляет соответствующие структурированные узлы, а не заменяет документ одним HTML-блоком. Редактор:

- обновляет название документа;
- переносит изменения текста, списков, таблиц, порядка и состава блоков в `WorkingDocument.nodes`;
- сохраняет исходный `template_id`, `section_id`, provenance и служебные флаги существующих узлов;
- помечает созданные вручную узлы как `manual-edit` и не приписывает им вымышленные ссылки на источники;
- хранит очищенный HTML как визуальное представление, которое сбрасывается и строится заново после сборки или чат-правки;
- не создаёт новый документ с жёстко заданным `use-case`.

Чат и повторная проверка читают обновлённый структурированный документ, поэтому учитывают ручные правки. Чат дополнительно получает нормализованные загруженные источники для grounding. Ручная правка не меняет тип документа и не уничтожает происхождение неизменённых или отредактированных существующих узлов.

## Палитра

Во всём рабочем интерфейсе применяется единая палитра, основанная на референсе:

- синий верхней панели: `#15569B`;
- основной синий для главного действия: `#1B5EAA`;
- графитовый текст и заголовки: `#202428`;
- вторичный текст: `#5F6873`;
- светлый нейтральный фон: `#F4F7FA`;
- границы, поля и неактивные поверхности: `#D6E5F8`.

Верхняя панель остаётся синей, как в TrackStudio. Рабочие панели и вторичные кнопки — белые. Заголовки панелей, основной интерфейсный текст, имена файлов, элементы управления и сообщения чата отображаются графитовым, а не синим. Заголовки непосредственно внутри листа редактируемого документа могут оставаться синими как часть корпоративного оформления документа. Основной синий также используется для главной кнопки «Собрать», ссылок, активной вкладки, фокуса поля и небольших статусных акцентов. Контраст текста и элементов управления сохраняется достаточным для длительной работы.

## Ошибки

Ошибки старта задания остаются безопасными и отображаются на рабочем экране. Ошибка сохранения визуального редактора не меняет структурный документ. Ошибки чата и проверки не выводят исходники, токены или внутренние исключения.

## Проверки

Автотесты покрывают:

- передачу выбранного шаблона при сборке и проверке;
- доступность проверки одного загруженного файла без предварительной сборки;
- сохранение исходного `template_id`, структуры и provenance при сохранении HTML редактора;
- наличие новой палитры на ключевых состояниях UI.

После изменений выполняются полный `pytest`, `ruff check .`, `git diff --check`, затем сквозной ручной прогон с настроенной локальной text-моделью.
